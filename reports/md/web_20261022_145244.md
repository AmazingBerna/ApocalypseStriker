## Fuori portata del Vulnerability Assessment passivo

Questa analisi legge soltanto ciò che l'applicazione espone a una normale richiesta (header, cookie, TLS, banner). Trova debolezze di **configurazione**; le vulnerabilità che si manifestano solo inviando input costruiti apposta (payload) restano fuori, per natura della fase.

| Categoria OWASP | Stato | Cosa riguarda |
|---|---|---|
| A01:2021 - Broken Access Control | **non testata** | controllo degli accessi: IDOR, accesso a funzioni o dati di altri utenti |
| A02:2021 - Cryptographic Failures | controllata (configurazione) | configurazione TLS: protocolli accettati, validità e scadenza del certificato |
| A03:2021 - Injection | **non testata** | injection: SQL injection, XSS, command injection |
| A04:2021 - Insecure Design | **non testata** | difetti di progettazione e di logica applicativa |
| A05:2021 - Security Misconfiguration | controllata (configurazione) | header di sicurezza mancanti o deboli, flag dei cookie, divulgazione di tecnologie |
| A06:2021 - Vulnerable and Outdated Components | controllata (configurazione) | versioni dichiarate nei banner con CVE note (NVD, KEV, EPSS) |
| A07:2021 - Identification and Authentication Failures | **non testata** | autenticazione e sessioni: bypass del login, brute force, gestione dei token |
| A08:2021 - Software and Data Integrity Failures | **non testata** | integrità di software e dati: deserializzazione insicura |
| A09:2021 - Security Logging and Monitoring Failures | **non testata** | logging e monitoraggio: non osservabili dall'esterno |
| A10:2021 - Server-Side Request Forgery (SSRF) | **non testata** | Server-Side Request Forgery (SSRF) |

> L'assenza di finding nelle categorie **non testate** non indica l'assenza di vulnerabilità: non sono state cercate. Richiedono il penetration testing attivo (OWASP ZAP), una fase separata soggetta a un'autorizzazione dedicata.

## Note metodologiche

Per ogni finding **Rischio = Impatto x Probabilità** (scala 1-5, punteggio 1-25). Soglie: 16-25 = Critico, 10-15 = Alto, 5-9 = Medio, 1-4 = Basso.

| Valore | Impatto (danno se sfruttato) | Probabilità (verosimiglianza) |
|---:|---|---|
| 1 | Trascurabile | Rara |
| 2 | Basso | Improbabile |

| 4 | Alto | Probabile |
| 5 | Critico | Quasi certa |

La ricognizione è **passiva**: legge header, cookie e TLS come farebbe un browser, senza inviare payload. I valori sono euristici (definiti in `apocalypsescan_app/config.py`, blocco VAPT web) e **non sostituiscono una verifica manuale**. Il penetration testing attivo (OWASP ZAP) è una fase separata, soggetta a una conferma dedicata.

Le **CVE note** vengono dal National Vulnerability Database, cercate per il CPE prodotto:versione letto nei banner (a NVD non arriva l'URL analizzato). La versione dichiarata dal banner può non corrispondere a quella reale e i pacchetti delle distribuzioni ricevono patch senza cambiare versione (backport): le CVE vanno verificate. La probabilità viene da CISA KEV ed EPSS quando disponibili, altrimenti dal vettore CVSS. Una versione nascosta o 0 CVE in NVD **non** provano l'assenza di vulnerabilità.
